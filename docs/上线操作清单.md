## 你现在需要做什么

没有剩余的上线配置任务。首次 GitHub 登录与内容同步已验证成功。换浏览器或退出登录后，在“发布与连接”点击“使用 GitHub 登录”即可。

网站资料和首批 7 篇文章已整理为个人内容初稿，具体内容可在后台逐步修改；入口与补充方向见 [内容修改指南](./CONTENT_GUIDE.md)。

## 写文章和发布

1. 进入“文章管理”，新建文章，填写标题、分类、摘要、日期和正文；封面可选。
2. 在富文本和 Markdown 模式之间选择。通过工具栏插入图片、链接、公式等，预览区核对排版。
3. “保存草稿”保留未发布内容，也可以按 `⌘/Ctrl+S`。草稿不会出现在前台。
4. 完成后“提交发布”，进入“发布与连接”查看待发布变更。
5. 点击“检查并发布”。检查未完成时稍后刷新；全部通过后合并到 `main`。
6. Cloudflare 自动构建并上线。后台的“已合并”表示内容已进入仓库；最终上线结果在上方 Cloudflare 部署记录确认，等待生产部署显示成功后刷新博客。

图片可先在“媒体资源”上传，再选择为封面、头像或插入正文。正在使用的图片受到引用保护，不能直接删除。

文章日期用于显示和排序，不是定时发布；点击发布后，未来日期的文章也会公开。

## 批量管理

文章管理与媒体资源支持逐项勾选、全选当前筛选结果和批量删除，每批最多 100 项。搜索或更换筛选条件会清空选择；删除前会列出内容名称、版本和数量，取消确认不会修改内容。

已发表文章与已上线图片会集中提交删除变更，列表显示“待删除”，到“发布与连接”检查并发布后前台正式移除。尚未发布的草稿从工作区撤回，已发表版本保留；需要恢复时，可在 GitHub 重新打开相应草稿 PR。

仍被文章、草稿或站点设置引用的图片会阻止整批删除。网络响应中断时，后台会重新确认 GitHub 的实际结果；已经成功提交的内容不会误报失败。部分操作仍未完成时，会显示完成数量并保留失败项的选择，刷新确认后可重试。

同步只重新读取改变的内容版本；保存和修改后直接更新返回结果。界面会显示正在核对、提交或合并的阶段，并防止重复点击。GitHub 构建检查和 Cloudflare 部署仍按原有发布流程完成。

## 以后换域名

把新域名发给我即可；如果位于新的 Cloudflare DNS 区域，提供该区域的访问授权。

更换时需要绑定新 Pages 自定义域名和 DNS，更新 `SITE_URL`、OAuth 来源白名单与应用 Homepage URL，然后重新构建。详细维护步骤见 [部署配置](./DEPLOYMENT.md)。

文章、图片、业务代码、OAuth Worker 地址和 Callback 均可继续使用，无需重新创建登录应用或密钥。
